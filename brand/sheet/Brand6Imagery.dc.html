Brand sheet · 06 · Visual and imagery style

Switches, flows and code

The imagery comes from the symbol and from what the library does: switches, sources flowing into one value, and code. It is flat, cool and structured. No people at laptops, no gradients, no 3D.
6.1
Graphic language
Three constructions taken from the symbol. Use one per layout, big and cropped, with the orange-red on the first element only. Never tile them across a page.
Stack. The symbol, large and cropped by the edge of the layout.
Switch. One pill with a knob, on its own, as a divider or a button shape.
Rows. Pills of different lengths, like a settings list. Orange-red on one or two rows only.
6.2
Diagrams
Diagrams carry most of the imagery. Sources are solid pills, the typed Config is an outlined box, and the single orange-red stroke marks the value arriving in the app.
6.3
Code screenshots
Code is shown as text in a rounded card with a 32 px inner margin, never as a window with traffic-light buttons. Light and dark cards match the page.
final case class AppConfig(host: String, port: Int) val appConfig: Config[AppConfig] = (Config.string("host") zip Config.int("port")) .map { case (h, p) => AppConfig(h, p) }

6.4
Icons
Line icons on a 48 px grid, a 3 px stroke with round caps. Ink strokes with one orange-red stroke per icon, on the part that changes or arrives.

6.5
Rules
One accent per picture. Orange-red marks one thing: the middle bar of the Z, the arriving value, the key part of an icon.
Round ends. Strokes and bars end in a full radius, like the pills in the symbol. Square ends only in code and tables.
Real content. Show real setting names and values, not lorem ipsum, and keep example values obviously fake (port 8080, localhost).
